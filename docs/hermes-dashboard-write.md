# запись в дашборд через hermes

статус: код и локальные проверки. боевые миграции, edge, ключ записи и настоящий telegram этим комплектом не включаются.

## что умеет агент

читатель с отдельным серверным разрешением показывает входящие. writer превращает одну выбранную запись в задачу на дату/в бэклог или цель в существующем горизонте и периоде. также создаёт и редактирует задачи и цели, переносит даты/периоды, изменяет прогресс цели. отдельного поля дедлайна нет.

каждый запрос показывает серверное «было / будет» и ждёт одно подтверждение. при конфликте ничего не переносится частично; нужно перечитать запись и подтвердить заново. выполнение задач, удаление без переноса, монеты, xp, школа, трекер и финансы недоступны writer. старый read token не даёт прав записи.

## установка на windows после готовности сервера

1. распакуй архив в отдельную папку, например `C:\Users\serv\.hermes\dashboard-writer`. существующий reader не перезаписывай.
2. из powershell запусти мастер со своим python из hermes venv:

~~~powershell
& 'C:\Users\serv\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe' `
  'C:\Users\serv\.hermes\dashboard-writer\dashboard_write_mcp.py' `
  --configure-write 'C:\Users\serv\.hermes\dashboard-writer-credentials'
~~~

мастер спросит project url, публичный legacy anon jwt и uuid того же аккаунта, что использует читатель. каталог должен быть новым, вне git, с ntfs acl только для нужной учётки/system/администраторов. токен записи лежит только в `dashboard-write.json`, в `dashboard-write.env` — hash и дата истечения. json, локальный sqlite и токен в чат, telegram или github не отправляй. `service_role` не вводится и на windows не хранится.

3. сделай резервную копию активного `config.yaml`. объедини блок `dashboard_write` из сгенерированного yaml с существующим `mcp_servers`, не заменяя читателя. проверь `timeout: 360` и `elicitation.enabled: true`, `elicitation.timeout: 300`. если `HERMES_HOME` изменён, используй его конфиг.
4. для входящих после включения на сервере обнови файл читателя из архива и добавь `get_inbox` в существующий `tools.include`. прежний reader credential не меняй.
5. проверь, что в telegram разрешён только твой числовой id и коннектор не открыт в групповых сессиях. перезапусти gateway штатным способом. реальную форму проверь до работы с обычными записями.

[справка hermes по формам подтверждения](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp#mcp-elicitation-support)

## порядок включения на сервере

- проверить и замержить stacked pr по порядку; не путать статус ci с выкладкой;
- сравнить историю и фактическую схему, применить только согласованные миграции; guard и write остаются false;
- выкатить frontend и reader с версиями, проверить фактически отдаваемые assets и отсутствие несохранённых локальных правок;
- после отдельного согласования включить cron-очистку, проверить один успешный job и только потом активировать guard владельца с write=false. существующий проект может не иметь pg_cron; его установка — отдельный шаг, не часть миграций;
- развернуть `dashboard-write` с `verify_jwt=true`, добавить только hash/expiry из env мастера, удостовериться, что `DASHBOARD_AGENT_USER_ID` соответствует существующему владельцу. проверить отрицательные сценарии при выключенном write;
- отдельно включить чтение входящих флагом `DASHBOARD_AGENT_INBOX_READ_ENABLED=true`; после проверки gateway включить write только этому владельцу;
- на синтетической записи проверить показ полного preview, отказ, повтор, подтверждение и появление результата на сайте. проверка из mac/stdin не доказывает работу кнопок в твоём telegram.

откат: выключить write, отозвать его hash, отменить оставшиеся drafts. guard и читатель остаются. при неизвестном сетевом результате не посылай ту же правку как новый запрос: коннектор восстанавливает статус прежнего id. если статус долго неизвестен, проверь состояние на сайте перед повтором. сброс sqlite не является способом повторить запрос.

техническая граница: подтверждение защищает обычный mcp-поток. агент с доступом к файлам той же windows-учётки может прочитать credential; защищай эту учётку и не выдавай ненужные права. тексты ответов могут попадать к провайдеру модели hermes; доступ к входящим включай только для доверенного контура.
