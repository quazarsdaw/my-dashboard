# синхронизируемые настройки предметных кабинетов школы

дата: 2026-07-29  
статус: утверждённый дизайн, реализация не начата

## контекст

в школьном интерфейсе уже определены шесть постоянных предметных кабинетов ChatGPT:

- Software Engineering;
- DevOps & Infrastructure;
- Mathematics;
- English & IELTS;
- University;
- Director & Assessment.

сейчас их URL задаются только статически в `school-teacher-config.js`. Это неудобно для пользователя и не синхронизируется между устройствами без изменения кода.

настройки кабинетов не являются содержимым уроков. они не должны записываться в Notion, менять 18 реальных карточек или расширять школьную базу данных. Notion остаётся единственным источником истины для уроков, а Supabase используется только для аккаунтной синхронизации пользовательской настройки интерфейса.

## цели

- позволить владельцу настроить шесть постоянных предметных кабинетов непосредственно на странице «Личная школа»;
- синхронизировать настройки между устройствами через существующий Supabase Auth и таблицу `user_data`;
- не создавать новую таблицу, Edge Function или поля Notion;
- сохранить текущий статический конфиг как безопасный fallback;
- не передавать промт, сведения об уроке или другие внутренние данные через URL.

## вне scope

- редактирование ссылок Codex, Cursor, Kimi, YouTube, книг, PDF и документации;
- хранение или редактирование маршрута отдельного урока;
- изменение четырёх маршрутных свойств урока в Notion;
- создание кабинетов для других платформ;
- добавление секретов или токенов;
- изменение существующих 18 уроков.

## выбранный интерфейс

### точка входа

в шапке страницы «Личная школа» появляется кнопка настроек:

- на desktop — иконка шестерёнки с доступным названием «Настройки школы»;
- на узком экране — компактная иконка с тем же `aria-label`;
- кнопка не заменяет вкладки «Сегодня», «Неделя» и «Дневник».

### панель настроек

кнопка открывает отдельную боковую панель:

- справа на desktop;
- почти на весь экран или как нижний sheet на mobile;
- с focus trap, закрытием по `Escape`, возвратом фокуса на кнопку и блокировкой фоновой прокрутки;
- с заголовком «Предметные кабинеты».

панель содержит ровно шесть строк. каждая строка показывает название предмета, поле URL и состояние проверки:

- «не настроено» — поле пустое;
- «готово» — URL прошёл проверку;
- «проверьте ссылку» — URL невалиден.

доступные действия:

- «Сохранить» — сохраняет все валидные изменения одним логическим действием;
- «Сбросить» около строки — очищает только выбранный пользовательский override;
- «Закрыть» — закрывает панель;
- при закрытии с несохранёнными изменениями показывается короткое подтверждение.

сохранение разрешено, если все непустые поля валидны. пустые поля допустимы: такой кабинет остаётся ненастроенным, а текущий fallback интерфейса позволяет скопировать промт без открытия внешней страницы.

## модель данных

в `public.user_data` используется одна строка с ключом:

```text
school_cabinet_urls_v1
```

значение строки имеет версионированную структуру:

```json
{
  "version": 1,
  "cabinets": {
    "chatgpt-software": "https://chatgpt.com/...",
    "chatgpt-devops": "https://chatgpt.com/...",
    "chatgpt-mathematics": "https://chatgpt.com/...",
    "chatgpt-english": "https://chatgpt.com/...",
    "chatgpt-university": "https://chatgpt.com/...",
    "chatgpt-director": "https://chatgpt.com/..."
  }
}
```

разрешены только перечисленные шесть ключей. неизвестные поля и неизвестные cabinet id игнорируются при чтении и не попадают в рабочую конфигурацию.

пустой URL не хранится как активный override. очистка удаляет соответствующий ключ из `cabinets`. если объект после очистки пуст, допустимо сохранить пустой версионированный объект, чтобы формат оставался однозначным.

Supabase-строка идентифицируется парой:

```text
(auth user id, school_cabinet_urls_v1)
```

для быстрого первого render разрешён только аккаунтный локальный cache:

```text
school_cabinet_urls_cache_v1:<auth user id>
```

cache не является источником истины и не проходит через общий localStorage-sync. его prefix добавляется в skip-правило `supabase-sync.js`. приложение никогда не читает cache без точного совпадения текущего `auth user id`.

## источник истины и приоритеты

для URL предметного кабинета применяется следующий приоритет:

1. валидный пользовательский override из `school_cabinet_urls_v1`;
2. URL из статического `SchoolLearningConfig.cabinets`;
3. отсутствие URL и существующий безопасный fallback «скопировать промт».

статический `SchoolLearningConfig` остаётся неизменяемым. при разрешении маршрута создаётся производная runtime-конфигурация с наложенными пользовательскими значениями. код не должен мутировать замороженный глобальный объект.

невалидный сохранённый override не подменяет статический URL. интерфейс показывает предупреждение, а resolver использует следующий безопасный уровень приоритета.

## синхронизация

настройки используют существующий Supabase client и существующую таблицу `user_data`, но отдельный узкий adapter:

```text
school-cabinet-settings adapter
→ public.user_data
→ realtime или refresh
→ аккаунтный локальный cache
→ school-cabinet-settings-applied
→ повторное разрешение маршрутов
```

новая таблица и отдельный сетевой протокол не создаются.

строка `school_cabinet_urls_v1` и prefix локального cache исключаются из общего массового sync. это предотвращает перенос настройки между аккаунтами через сохранённый localStorage при logout или смене пользователя. adapter всегда получает текущую сессию через существующий `SupabaseSync`/Supabase Auth и указывает `user_id` текущего пользователя.

после нажатия «Сохранить»:

1. draft нормализуется и валидируется;
2. выполняется прямой upsert строки `(current user id, school_cabinet_urls_v1)` через существующий Supabase client;
3. после успешного ответа обновляются аккаунтный cache и рабочая конфигурация;
4. adapter публикует событие `school-cabinet-settings-applied`;
5. пользователь видит подтверждение облачного сохранения.

если облачная отправка не удалась, draft остаётся в открытой панели, но не выдаётся за синхронизированную настройку и не заменяет подтверждённый cache. пользователь может повторить сохранение. тихая фоновая очередь в MVP не добавляется.

при получении realtime-обновления или результата refresh:

- если панель закрыта или draft не изменён, новые значения применяются сразу;
- если в открытой панели есть несохранённый draft, он не перезаписывается молча;
- показывается сообщение «Настройки изменены на другом устройстве» с действиями перечитать облачную версию или сохранить текущий draft.

конфликт разрешается на уровне всего ключа по существующей семантике `updated_at`: последнее успешное сохранение побеждает. для редкой настройки одного владельца это приемлемо и не требует отдельной схемы с шестью строками.

при входе, смене аккаунта и выходе adapter сбрасывает runtime-состояние до определения текущего пользователя. cache предыдущего пользователя не применяется и не отправляется от имени нового пользователя.

## валидация URL

каждый непустой URL проверяется до сохранения и повторно перед внешним открытием.

требования:

- абсолютный URL;
- схема только `https:`;
- максимум 2048 Unicode code points;
- hostname только `chatgpt.com` или `chat.openai.com`;
- username и password отсутствуют;
- запрещены `http:`, `file:`, `javascript:`, `data:`, `notion:` и любые другие схемы;
- строка нормализуется через стандартный `URL`, но не обрезается автоматически;
- query и fragment могут сохраняться как часть пользовательской ссылки, однако приложение никогда не добавляет в них промт или данные урока.

проверка hostname должна быть точной. значения вроде `chatgpt.com.example.org` или `evilchatgpt.com` не допускаются.

## безопасное открытие кабинета

настройка меняет только источник постоянного URL. существующий pre-open flow остаётся обязательным:

1. синхронно открыть `about:blank` внутри пользовательского click;
2. сохранить window handle;
3. выполнить `startLesson`;
4. после успеха сформировать и скопировать prompt;
5. повторно провалидировать уже разрешённый URL;
6. установить `popup.opener = null`;
7. выполнить `popup.location.replace(validatedUrl)`;
8. при ошибке закрыть popup.

prompt и внутренние данные не передаются через URL или query parameters.

## авторизация и защита данных

URL кабинетов не являются секретами, но являются пользовательскими данными.

до реализации необходимо подтвердить фактическое состояние `public.user_data`:

- RLS включён;
- прямой доступ разрешён только роли `authenticated`;
- `select`, `insert`, `update` и `delete` ограничены условием `(select auth.uid()) = user_id`;
- update не может изменить `user_id` на чужой, то есть имеет корректные `using` и `with check`;
- анонимный пользователь не может читать или менять строки;
- один пользователь не может читать или менять данные другого.

если эта защита отсутствует или расходится с ожидаемой, это считается отдельной security-проблемой. сначала оформляется GitHub issue по правилам репозитория, затем исправление выполняется отдельной миграцией. feature-PR не должен молча расширять scope или обходить RLS через service role.

во frontend остаётся только публичный/anon Supabase key. service role, Notion token и другие секреты не добавляются.

## обработка ошибок

- повреждённый JSON игнорируется, интерфейс показывает нейтральное предупреждение и продолжает работать со статическим fallback;
- неизвестная версия не применяется автоматически;
- неизвестные cabinet id игнорируются;
- ошибка localStorage не маскируется сообщением об успешном сохранении;
- ошибка Supabase отделяется от локальной ошибки;
- невалидный URL не сохраняется и не открывается;
- входящий sync не должен закрывать открытый урок или панель настроек.

## доступность и mobile

- все поля имеют видимые label;
- ошибки связаны с полями через `aria-describedby`;
- итоговое состояние сохранения объявляется через `aria-live`;
- focus trap и возврат фокуса повторяют существующее поведение школьных диалогов;
- интерактивные элементы имеют touch target не меньше 44×44 px;
- на mobile длинный URL не растягивает страницу по горизонтали;
- системная клавиатура использует подходящий режим для URL.

## тестирование

### unit

- чтение корректной версии настройки;
- отклонение повреждённого JSON и неизвестной версии;
- allowlist из шести cabinet id;
- приоритет override → static config → copy-only fallback;
- очистка одного override не меняет остальные;
- точная проверка hostname;
- отклонение HTTP, credentials и URL длиннее 2048 code points;
- производная конфигурация не мутирует статический объект.

### frontend integration

- открытие и закрытие панели, focus trap и возврат фокуса;
- сохранение шести полей одним ключом;
- частично заполненная конфигурация;
- повторный render маршрутов после локального сохранения;
- обработка `school-cabinet-settings-applied`;
- входящий sync без draft применяется сразу;
- входящий sync при dirty draft не затирает изменения;
- ошибка cloud upsert сохраняет draft и не подменяет подтверждённую настройку;
- смена аккаунта не читает и не отправляет cache предыдущего пользователя;
- общий localStorage-sync игнорирует remote key и prefix cache;
- сброс восстанавливает статический fallback;
- pre-open flow использует новый URL без передачи prompt через URL.

### Supabase security

- владелец может читать, создавать, обновлять и удалять собственный ключ;
- другой авторизованный пользователь не может прочитать или изменить ключ владельца;
- неавторизованный запрос не получает данные;
- update не позволяет подменить `user_id`;
- проверяется Security Advisor для затронутых объектов.

### browser и visual QA

- desktop Chrome/Safari;
- mobile viewport и фактический touch flow;
- popup-разрешённый и popup-заблокированный сценарии;
- сохранение, reload и получение настройки во втором браузерном контексте;
- отсутствие горизонтального overflow;
- корректное отображение длинной, но валидной ссылки.

## влияние на проект

- Notion и состав 18 уроков не меняются;
- `school-teacher-config.js` остаётся источником defaults, но перестаёт быть единственным способом задать URL;
- `school-learning-route.js` получает runtime overlay перед разрешением маршрута;
- отдельный settings adapter отвечает за чтение, запись, realtime и аккаунтный cache;
- `school.js`, `school.html` и `school.css` получают панель настроек и реакции на sync;
- `supabase-sync.js` получает узкое skip-правило, чтобы общий sync не обрабатывал remote key и аккаунтный cache;
- README обновляется с описанием нового приоритета источников.

## стратегия веток и PR

работа выполняется отдельным stacked PR:

- base — ветка PR #53 `agent/school-learning-routes-readonly`;
- новая ветка — `agent/school-cabinet-settings`;
- в PR входят design doc, реализация, тесты и документация только для настроек шести кабинетов;
- после merge PR #53 следующий PR retarget/rebase на `main`;
- после retarget проверяется чистота diff и повторно запускаются все релевантные тесты;
- PR не переводится в merge автоматически.

## критерии готовности

- настройки доступны из шапки «Личной школы»;
- редактируются только шесть предметных ChatGPT-кабинетов;
- значения синхронизируются между устройствами одного аккаунта;
- данные другого пользователя недоступны;
- невалидная ссылка не сохраняется и не открывается;
- маршруты уроков используют пользовательский override без изменения Notion;
- очистка возвращает статический fallback;
- существующий copy-only fallback работает для незаполненных кабинетов;
- prompt и внутренние данные не попадают в URL;
- desktop/mobile UI и popup flow проверены;
- тесты frontend, route resolver и Supabase security проходят;
- PR остаётся отдельным, подробным и не мержится автоматически.
