# Приоритеты и периоды целей — дизайн

## Контекст

Текущая страница `goals.html` хранит цели в `horizons_goals_v2`, разделяет их по шести горизонтам и показывает все цели горизонта одним списком. У цели нет приоритета и конкретного периода, поэтому нельзя отличить октябрьские цели от ноябрьских, вернуться к истории недели или перенести активную цель в другой период.

Новый интерфейс сохраняет существующие горизонты и визуальный язык дашборда, но добавляет внутрь каждого горизонта навигацию по периодам и явный приоритет.

## Утверждённая модель

### Горизонты

Поддерживаются все существующие горизонты:

- `week` — неделя, с понедельника по воскресенье;
- `month` — календарный месяц;
- `quarter` — календарный квартал;
- `year` — календарный год;
- `5year` — пятилетний блок, привязанный к сетке `2026–2030`, `2031–2035`, `2021–2025` и далее;
- `life` — единственный бессрочный период.

Календарные расчёты выполняются в `Asia/Yekaterinburg`, чтобы границы недели и текущий период не зависели от часового пояса устройства.

### Канонические ключи периодов

- неделя: дата понедельника в формате `YYYY-MM-DD`;
- месяц: `YYYY-MM`;
- квартал: `YYYY-QN`;
- год: `YYYY`;
- пять лет: начальный год блока, например `2026`;
- жизнь: `life`.

### Приоритеты

- `p1` — красный;
- `p2` — жёлто-оранжевый;
- `p3` — синий;
- `p4` — зелёный.

На карточке приоритет обозначается небольшим флагом у начала строки и слабым градиентом, который исчезает в обычный фон карточки. Полоса прогресса остаётся нейтральной и не конкурирует с приоритетом.

### Схема данных

Сохраняется существующий синхронизируемый ключ `horizons_goals_v2`. Новая версия данных:

```js
{
  schemaVersion: 3,
  goals: [{
    id: 'goal-id',
    title: 'Название цели',
    horizon: 'month',
    periodKey: '2026-10',
    priority: 'p3',
    order: 100,
    type: 'check',
    target: 1,
    unit: '',
    current: 0,
    done: false
  }]
}
```

`periodKey`, `priority` и `order` являются частью синхронизируемой модели. Отдельное хранилище и frontend-only состояние для них не создаются.

### Миграция

При первом чтении старых данных:

- отсутствующий `priority` становится `p3`;
- отсутствующий `periodKey` становится текущим периодом соответствующего горизонта;
- для `life` всегда используется `life`;
- отсутствующий `order` назначается как `100`, `200`, `300` внутри группы `horizon + periodKey + priority` в исходном порядке;
- старые поля цели сохраняются без изменения;
- миграция идемпотентна и не мутирует входной объект;
- нормализованные данные сохраняются одним вызовом общего `Gamification.storeSet`, поэтому продолжают синхронизироваться существующим механизмом.

## Интерфейс

### Общая композиция

Используется утверждённый вариант «Навигатор»:

- сверху остаётся годовой сводный блок;
- ниже остаются шесть аккордеонов горизонтов;
- раскрытый горизонт показывает компактный навигатор периода, список целей и соседние drop-зоны;
- страница остаётся в существующем центральном контейнере и не превращается в полноэкранный календарь.

### Годовой сводный блок

- позволяет выбрать год;
- показывает долю прошедшего календарного года и количество выполненных годовых целей выбранного года;
- месяцы становятся кнопками;
- нажатие на месяц раскрывает горизонт «Месяц» и выбирает соответствующий период;
- кнопки имеют доступные названия и видимый `focus-visible`.

### Навигатор периода

В каждом горизонте доступны:

- предыдущий период;
- селектор периода;
- следующий период;
- «Сегодня» для возврата к текущему периоду.

Подписи:

- неделя: `5–11 октября 2026`;
- месяц: `Октябрь 2026`;
- квартал: `4 квартал 2026`;
- год: `2026 год`;
- пять лет: `2026–2030`;
- жизнь: `Вся жизнь`.

Выбранные периоды являются состоянием интерфейса и хранятся отдельно от данных целей в `goals_period_selection_v1`, чтобы reload сохранял контекст просмотра. Это состояние не меняет принадлежность целей к периодам.

### Список целей

В выбранном периоде:

1. активные цели сортируются `p1 → p2 → p3 → p4`;
2. внутри одного приоритета действует ручной `order`;
3. выполненные цели показываются ниже активных и остаются в исходном периоде;
4. пустое состояние объясняет, что цель можно создать для выбранного периода.

На карточке показываются флаг и label приоритета, название, прогресс и действие «Перенести» для активной цели. Выполненная цель визуально приглушена, но не исчезает.

### Создание и редактирование

Форма новой цели получает поля:

- горизонт;
- конкретный период выбранного горизонта;
- приоритет, по умолчанию `p3`;
- существующие тип, цель и единица измерения.

Редактор существующей цели позволяет изменить название, прогресс и приоритет. Для активной цели также доступно отдельное действие «Перенести».

## Перенос и ручной порядок

### Активные цели

Активную цель можно переносить в прошлый или будущий период того же горизонта. Горизонт цели не меняется обычным переносом.

На desktop:

- drag-and-drop внутри списка меняет порядок только среди целей того же приоритета;
- drop на соседнюю зону переносит цель в предыдущий или следующий период;
- во время drag показывается явный preview назначения;
- после drop выполняется одна запись в хранилище.

На mobile и с клавиатуры используется кнопка «Перенести», открывающая доступный выбор любого периода того же горизонта. Этот же путь остаётся доступен на desktop для далёких периодов.

Если приоритет меняется, цель помещается в конец новой приоритетной группы выбранного периода.

### Выполненные цели

Выполненная цель остаётся исторической записью исходного периода:

- её нельзя перетащить или перенести;
- действие переноса не показывается;
- пользователь может создать повтор цели в другом периоде как новую невыполненную цель, но исходная запись не изменяется.

### Порядок

`order` локален для группы `horizon + periodKey + priority`. После изменения порядка только затронутые группы получают последовательность `100`, `200`, `300` и далее. Дубли и некорректные значения исправляются нормализацией соответствующей группы.

## Доступность и responsive

- все действия доступны без drag-and-drop;
- touch-targets не меньше 44px;
- фокус возвращается на инициировавшую кнопку после закрытия диалога;
- изменение периода и перенос объявляются через `aria-live`;
- цвет приоритета дублируется текстом `P1`–`P4`;
- motion ограничен 150–250 мс и отключается через `prefers-reduced-motion`;
- на узком экране навигатор переносится на две строки, а карточка сохраняет читаемую иерархию без горизонтального overflow.

## Ошибки и повреждённые данные

- неизвестный горизонт нормализуется в `year` только для старой записи без поддерживаемого значения;
- неизвестный приоритет нормализуется в `p3`;
- некорректный `periodKey` заменяется текущим периодом соответствующего горизонта;
- повреждённый `order` восстанавливается внутри своей группы;
- неизвестные дополнительные поля не используются интерфейсом и не должны влиять на сортировку;
- пустое название по-прежнему не сохраняется.

## Не входит в работу

- отдельная серверная база целей;
- новые таблицы Supabase;
- уведомления и автоматический перенос просроченных целей;
- зависимости между целями;
- изменение горизонта через drag-and-drop;
- удаление истории выполненных целей.

## Критерии готовности

- существующие цели после миграции находятся в текущих периодах с `p3` и не теряют прогресс;
- недели всегда начинаются в понедельник и заканчиваются в воскресенье по Екатеринбургу;
- выбранный период сохраняется после reload;
- P1/P2/P3/P4 отображаются утверждёнными цветами, а progress-bar остаётся нейтральным;
- активную цель можно перенести в прошлый и будущий период;
- выполненную цель нельзя перенести, и она остаётся доступна в истории;
- ручной порядок сохраняется после reload и синхронизации;
- desktop и mobile состояния визуально проверены;
- полный набор тестов проходит без ошибок.
