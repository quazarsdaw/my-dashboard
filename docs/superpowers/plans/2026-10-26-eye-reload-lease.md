# восстановление разминки после reload

связано с issue #67 и pr #65. причина: pagehide не гарантирует завершения async mutex перед уничтожением документа.

1. regression-first: воспроизвести синхронный отзыв владения и требование ui не запускать async release на pagehide.
2. добавить отдельную синхронную отметку отзыва для token + instanceid. не удалять и не перезаписывать сам lease вне mutex; новый claim учитывает отметку и создаёт новый token под mutex.
3. чужой экземпляр не может отозвать текущий lease; старый экземпляр после takeover не влияет на новый. следующий claim очищает служебную отметку старого token.
4. pagehide сохраняет паузу и вызывает синхронный отзыв; обычные release остаются под mutex.
5. проверить немедленный reload и bfcache в browser acceptance с web locks и indexeddb fallback, полный frontend suite и синтаксис; обновить версии assets.

red: оба новых теста упали до реализации — отсутствовал retireSession, pagehide не вызывал синхронный отзыв. существующие тесты зелёные.

green: 537/537 frontend, 108/108 прежний backend и typecheck; синтаксис изменённых скриптов и diff-check без ошибок. изолированный chrome подтвердил восстановление без ожидания ttl для web locks и indexeddb; защита от cloned tab и старого token сохранена.

ревью исходного candidate нашло один important #67, других подтверждённых дефектов нет. новый фикс проверен автором через red→green и browser acceptance, без второго независимого review. production, реальные аккаунты/rls и физические звук/вибрация не проверялись; межустройственная атомарность монет не добавлялась.
